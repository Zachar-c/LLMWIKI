# 答辩素材草稿

**状态：准备材料，不是学校最终题目或已经完成的实验。用户确认目前尚未向学校提交题目。**

## 可与导师沟通的题目

《基于大语言模型与知识检索的软件测试辅助系统设计与实现》

系统现有范围包含资料管理、Wiki 草稿、参考资料检索、测试用例生成与审查。题目只是建议，最终以导师和学校确认内容为准。早期开题草稿包含知识问答和对照实验；当前实现尚无独立知识问答和正式对照实验，需与老师核实最终要求，不应说已经实现。

## 建议 PPT 结构（3—5 分钟）

1. **问题和目标**：测试资料分散，人工查找和整理用例耗时；目标是根据选定资料生成可追溯的用例草稿，保留人工审核。
2. **需求与范围**：资料管理、知识页整理、资料检索、用例生成与审查、人工确认和导出；不自动执行被测系统。
3. **系统设计**：Vue 网页 → FastAPI 后端 → SQLite；后端使用 OpenCode 调用 DeepSeek，生成结果保存并显示原文来源。说明资料由用户提供，模型输出需要核对。
4. **主要流程演示**：导入自编资料 → 生成并核对 Wiki → 输入需求并生成用例 → 查看原文 → 审查 → 人工确认 → 导出 CSV。
5. **测试与不足**：说明已经实测的项目功能与模型类型，区分模拟模型与真实模型；当前检索采用词项匹配，模型可能生成无依据内容，免费模型可能受额度限制。
6. **总结**：展示系统如何把资料、生成结果和人工审核连接起来，明确后续可改进检索质量和模型稳定性。

## 讲解提示

“系统首先保留资料原文及来源，随后把选定内容整理为待人工确认的知识页。在生成用例时，系统根据需求检索资料与已发布知识页，将检索结果交给模型，结果作为草稿展示。用户可以回看原文、审阅建议、编辑用例，并在人工确认后导出。系统使用词项匹配，不把模型生成视作测试执行结果。”
