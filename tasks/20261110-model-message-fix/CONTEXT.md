# 模型额度提示修正记录

## 依据与范围

2026-11-10 继续用户授权的毕设开发。实际读取工作区 `AGENTS.md`、`README.md`、catalog 毕设项目/资产/路径/关系记录；本项目 `README.md`、`tasks/20261110-real-browser-acceptance/CONTEXT.md`、`验收复现说明.md`、`backend/app/web_opencode.py`、`backend/app/opencode_web_model.py` 及相关测试。仅在该项目范围工作，没有读取公司数据或扫描其他历史目录。正式题目和导师最终要求仍未确认。

此前 DeepSeek 与用户允许临时使用的 MiMo 均在网页真实验收中返回额度或频率限制；旧适配器对该类错误固定显示 DeepSeek，导致 MiMo 结果展示了错误的模型名。本轮新增 `backend/app/web_opencode_fixed.py`、`backend/tests/test_model_message_fix.py` 和 `start-web-opencode-fixed.cmd`，保留原文件与默认数据库。新入口复用旧路由和适配器，仅对旧的固定额度提示做通用化，其余错误与成功结果保持原样；该包装依赖原错误文案完全相等，原文变更时需要复核。

## 执行与结果

- 在添加新入口前执行测试，因模块不存在失败；实现后 3 项检查通过，覆盖 Wiki 和用例生成的额度错误与不落库、其他错误保留、成功返回不变。均使用临时 SQLite 和模型替身。独立审查还用临时数据库确认审查请求失败不会保存 review。
- 后端完整测试 38 项中 36 项通过、2 项因 8000 端口占用跳过，自动测试包含模型替身。
- 本机 OpenCode 2.2.6 实际请求所选 DeepSeek，仍报告免费额度限制。随后通过新入口和独立临时数据库实际调用，返回 503 及通用额度/频率提示，Wiki 草稿数为 0。这验证真实失败处理，不代表真实生成成功。
- 通过新启动文件启动本机 8012；首页和健康接口为 200，能读取原有 1 条自编资料、1 条 Wiki 草稿、1 个用例批次。旧 8011 未停止，仍使用旧提示；新旧入口使用相同本机数据库。
- 新增 `网页演示入口-修正版.md` 说明启动与边界。无代码或数据迁移到外部平台，无公司材料复制。
