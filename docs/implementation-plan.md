# 智能测试用例系统实施计划

依据用户引用的老师沟通截图与会话摘要，核心流程：资料导入 → Wiki 整理与人工发布 → 输入需求 → 检索资料/Wiki → AI 生成用例 → AI 审查 → 人工编辑并保存 → CSV 导出；MCP 本机调用共用相同后端接口。正式题名以学校确认材料为准。

Vue + FastAPI + SQLite 单机运行；沿用已验证资料模块。小规模语料先使用可解释的中文词项检索，将已发布 Wiki 和原始片段作为上下文，记录来源；最多 6 项，正文和引用原文合计最多 12000 字符，超出预算的整项跳过。生成与审查使用一个 OpenAI 兼容接口；没有配置时明确报错，绝不填充虚构结果。人工审查与 AI 审查分开，编辑后将旧审查标记过期。MCP 采用官方 Python SDK 的本地 stdio，调用同一服务。

1. 创建独立工作副本，原始文件逐项校验并记录来源。
2. 独立完成 Wiki 草稿、人工编辑/发布及来源检查。
3. 完成检索、生成、保存、审查、导出，保留模型和资料引用。
4. 前端接入资料、Wiki 和用例操作；无需账号和复杂后台。
5. 完成 MCP 客户端握手与真实工具调用检查。
6. 基于自编文本运行本地接口、浏览器及失败路径；真实模型若无配置，记录为未验证，不能用测试替身冒充真实调用。

暂不实现爬虫、自动测试执行、生成测试数据、复杂多智能体和技术路线对照实验。公司项目只参考架构思路，代码许可待核实；不得导入公司数据。已有 Demo 路径尚未给出，获得路径后按范围检查并评价能否复用。
